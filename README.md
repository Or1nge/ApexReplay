# Apex回放

本地 Windows Apex 自动素材采集器。WPF 界面、C++ 工作进程、Windows 窗口与进程音频采集、GPU 缩放及 H.264 / H.265 NVENC 编码。无需管理员权限、云服务或大模型。

[下载 Windows 运行包](https://github.com/Or1nge/ApexReplay/releases/tag/v0.1.0-preview)。要求 Windows 11、支持 NVENC 的 NVIDIA 显卡和可用的中文 Windows OCR。解压整个 ZIP 后即可运行，无需另外安装 .NET。

## 使用

打开解压目录中的 `Apex回放/Apex回放.exe`，选择保存位置，点击“开始采集”。从源码构建的程序位于 `dist/Apex回放`。Apex 窗口出现后自动开始缓存；游戏退出后继续等待。关闭窗口会收进托盘；托盘菜单“退出”会结束工作进程。

界面有浅色和深色两种外观，标题栏右侧可切换；默认“自动”按电脑本地时间切换，7:00–19:00 为浅色，其余时间为深色。

素材目录、麦克风设备、麦克风降噪、声音平衡、缓存上限、片段时长、视频画质配置和界面外观会在修改后立即记住，下次启动自动恢复；关闭窗口和退出时也会保存。

采集默认通过 Windows 的无边框权限接口关闭黄色提示框；若系统未允许，界面会说明。另一个正在采集同一游戏窗口的程序也可能让系统继续显示边框。

“视频”“缓存与片段”“声音”中可以调整：

- 最长缓存：默认 **30 分钟**，范围 1–120 分钟。
- 闲置内存占比：默认 **60%**，范围 10–90%。两项上限同时生效，不会为了凑够时长超出内存预算。
- 长镜头开始前、结束后的保留时长；仅保存连续交战中的多次击倒 / 淘汰，不单独保存一次爆发。
- 麦克风设备及“自己/其他声音”的平衡。
- 自己的麦克风降噪，默认开启，可在采集时切换；在响度平衡和编码前抑制持续背景噪声，仅作用于麦克风音轨。

缓存存放编码后的数据，保存只引用对应历史，不会清空缓存。系统内存预算每约 2 秒更新；计算时补回本软件已分配的编码缓存，避免自己的增长导致预算不断缩小。游戏或其他程序占用更多内存时，优先释放最旧的完整关键帧区间。候选和导出引用也计入预算；无法释放足够内存时停止采集并显示错误。30 分钟 60 Mbps 视频约需 12.6 GiB，实际码率、音轨和空闲内存会影响保留量。

视频固定 60 fps，默认跟随游戏分辨率，也可固定为 1080p、1440p、4K；可选 HEVC / H.265 或 H.264、10–200 Mbps VBR 目标码率，以及性能优先 / 均衡 / 画质优先预设。默认跟随游戏分辨率、HEVC、60 Mbps、画质优先；选择 1080p 等固定分辨率后会记住，重启仍保持所选值；VBR 瞬时峰值允许达到目标的 1.5 倍。视频配置停止采集后修改，下次启动采集生效。MP4 带三个独立 48 kHz AAC 音轨：Apex、自己麦克风、其他桌面声音。第三轨由系统排除 Apex 进程树，包含 Oopz、KOOK、Discord、Chrome、Edge 等。麦克风和第三轨做有门限的平滑响度调整及峰值限制；不会回放麦克风。普通播放器通常只播放一个音轨，剪辑软件可以加载三个音轨。

“声音”中的三条电平用于确认各轨是否录到声音：开始采集并找到 Apex 窗口后约每秒刷新 10 次，显示该间隔内录入音轨的峰值。电平条采用 −60 到 0 dBFS 的刻度，右侧显示数值；低于 −60 dBFS 显示“静音 / 极低”，设备失败显示“设备不可用”。尚未采集或正在等待游戏时显示对应状态，此时不会监听麦克风。

结果确认后会等待最多 20 秒，判断是否出现关联击倒。这个等待不会全部加到视频尾部。只导出连续交战长镜头，单次爆发不单独输出。最长连续素材为 90 秒，分段留 2 秒衔接；同一长镜头的末段即使只剩一次结果也会保留。素材目录只输出 MP4，不再写视频旁的 JSON 说明文件。失败任务在本次运行期间保留引用，可以重试；退出进程后内存任务无法恢复，已有 MP4 和临时文件不会被删除。

## 目前验证范围

这是可运行的早期版本。已在本机验证真实 Windows 窗口采集、NVENC、三个音轨、重叠导出、保存失败后重试，并用本地 2024 年参考录像运行真实解码、HUD 识别和规则处理。规则场景测试包含五次跨队击倒、长追击切断、重复淘汰、助攻、换弹、90 秒分段和动态内存预算。

HUD 适配首先针对这些参考录像中的中文布局。数字采用本地二值字形匹配，中央提示采用 Windows 本地 OCR；没有 YOLO 或大模型。自己的 HUD 名字经多次确认后，用于匹配本人击杀信息，只补充已有中央结果提示的目标身份，不把其他玩家的消息直接当作本人结果。目标名仍不清晰时记录带标记的结果身份，采用提示生命周期去重，避免猜测敌人队伍。观战、大厅、结算、训练场或无法匹配关键 HUD 的画面不会继续触发素材。

伤害计数不可读时，只要武器弹药和战斗布局仍可确认，就继续识别本人结果提示，连杀可依据确认的击倒/淘汰结果保存；不依赖敌人的血条。计数恢复后重新建立伤害基线，不把遮挡期间的累计变化猜成瞬间高伤。单次结果和单独助攻均不输出镜头。

**尚未通过当前版本 Apex 的实战验收，也尚未证明总体精度 ≥95%、召回 ≥90%、误存 ≤10%、游戏平均帧率下降 ≤5%。**小样本回归不能替代留出集。详细证据和限制见 `docs/VALIDATION.md`。实战建议使用无边框窗口；采集受限会报错，不会改用注入或渲染挂钩。

## 诊断与开发

设置位于 `%LOCALAPPDATA%\ApexPerif\settings.json`，会话日志位于 `%LOCALAPPDATA%\ApexPerif\logs`。源代码见 `src/`，规则和中文字形模板见 `config/`。

开发构建与诊断命令见 `docs/BUILD.md`。运行包自带 .NET 和 FFmpeg 动态库，第一版需要 Windows 11、支持 HEVC NVENC 的 NVIDIA 显卡及可用的中文 Windows OCR。

系统边界：不注入、不挂钩游戏渲染、不读写游戏内存、不安装驱动、不修改游戏文件、不自动操作游戏。只读取窗口与进程基本信息，使用系统采集接口。没有 EA 认证，也不能保证反作弊零误判。[EA 游戏规则](https://help.ea.com/en/articles/apex-legends/play-by-the-rules/)
