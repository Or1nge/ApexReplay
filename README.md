# Apex回放

本地 Windows Apex 自动素材采集器。WPF 界面、C++ 工作进程、Windows 窗口与进程音频采集、GPU 缩放及 H.264 / H.265 NVENC 编码。无需管理员权限、云服务或大模型。

[下载 Windows 运行包](https://github.com/Or1nge/ApexReplay/releases)。要求 Windows 11、支持 NVENC 的 NVIDIA 显卡和可用的中文 Windows OCR。解压整个 ZIP 后即可运行，无需另外安装 .NET。

## 使用

打开解压目录中的 `Apex回放/Apex回放.exe` 后自动开始采集并等待 Apex，无需点击录制按钮。默认保存到系统“视频”目录下的 `Apex回放`；已有保存位置会继续使用。从源码构建的程序位于 `dist/Apex回放`。Apex 窗口出现后自动开始缓存；游戏退出后继续等待。关闭窗口会收进托盘；托盘菜单“退出”会结束工作进程。

在“设置 › 通用”打开“开机自启”后，登录 Windows 时会在托盘启动并自动等待 Apex；关闭开关即取消。重复打开应用会唤回已有窗口，不会启动第二个采集器。

“概览”页列出保存目录中最新的片段（含 Windows 视频缩略图），点击即可播放。概览和托盘菜单中的“保存全部缓存”会把当前缓存里的整段录像（从最早的关键帧到最新画面）立即保存成一个 MP4，文件名类型为“手动”，列表中显示为“手动保存”；保存期间采集继续，同一时间只进行一次整段保存。界面有浅色和深色两种外观，在“设置 › 通用 › 外观”切换；默认“自动”按电脑本地时间切换，7:00–19:00 为浅色，其余时间为深色。

素材目录、麦克风设备、麦克风降噪、声音平衡、缓存上限、片段时长、伤害标准、开机自启、开发者模式、视频画质配置和界面外观会在修改后立即记住，下次启动自动恢复；关闭窗口和退出时也会保存。

采集默认通过 Windows 的无边框权限接口关闭黄色提示框；若系统未允许，界面会说明。另一个正在采集同一游戏窗口的程序也可能让系统继续显示边框。

“设置”页中可以调整：

- 最长缓存：默认 **30 分钟**，范围 1–120 分钟。
- 闲置内存占比：默认 **60%**，范围 10–90%。两项上限同时生效，不会为了凑够时长超出内存预算。
- 片段开始前、结束后的保留时长。
- 保存标准：默认 **5 秒内累计伤害 ≥250**，且这段时间内存在 **2 秒伤害 >150**；两个条件必须同时满足，并有本人击倒、淘汰或助攻提示。换弹、切枪和技能伤害也计入同一个时间窗口；纯伤害没有结果提示不保存。四项均可拖动滑块或输入数字，回车或离开输入框生效；连续击倒多人仍自动保存长镜头。
- 麦克风设备，以及自动人声平衡之后“麦克风/其他声音”的偏向（−12 到 +12 dB）。
- 自己的麦克风降噪，默认开启，可在采集时切换；在人声平衡和编码前抑制持续背景噪声，仅作用于麦克风音轨。

缓存存放编码后的数据，保存只引用对应历史，不会清空缓存。系统内存预算每约 2 秒更新；计算时补回本软件已分配的编码缓存，避免自己的增长导致预算不断缩小。游戏或其他程序占用更多内存时，优先释放最旧的完整关键帧区间。候选和自动片段的导出引用也计入预算；无法释放足够内存时停止采集并显示错误。“保存全部缓存”边写边释放已写入的部分，它暂时持有的数据不计入缓存预算，所以不会为此清空缓存或停止采集；磁盘很慢时，内存占用可能短暂超过上限。30 分钟 60 Mbps 视频约需 12.6 GiB，实际码率、音轨和空闲内存会影响保留量。

视频固定 60 fps，默认跟随游戏分辨率，也可固定为 1080p、1440p、4K；可选 HEVC / H.265 或 H.264、10–200 Mbps VBR 目标码率，以及性能优先 / 均衡 / 画质优先预设。默认跟随游戏分辨率、HEVC、60 Mbps、画质优先；选择 1080p 等固定分辨率后会记住，重启仍保持所选值；VBR 瞬时峰值允许达到目标的 1.5 倍。视频配置停止采集后修改，下次启动采集生效。MP4 带三个独立 48 kHz AAC 音轨：Apex、自己麦克风、其他桌面声音。第三轨由系统排除 Apex 进程树，包含 Oopz、KOOK、Discord、Chrome、Edge 等。麦克风和第三轨做动态人声平衡（见下文），Apex 音轨只做峰值限制；不会回放麦克风。普通播放器通常只播放一个音轨，剪辑软件可以加载三个音轨。

### 人声平衡

麦克风（第二轨）和其他桌面声音（第三轨）各自持续检测人声：每 10 ms 分析一次音高、语调变化、频谱变化和谐波分布。人声需要处在人声音高范围内、高于背景噪声，并且音高随语调移动、谐波和共振峰随发音变化；提示音、铃声、蜂鸣声保持固定音高，或在鸣响时只有几条不变的谱线，或基频高于人声范围，因此不算人声。键盘、鼠标、风扇等噪声也不算。

只有确认是人声的片段才用来测量这一轨“正常说话”的音量：长期值约覆盖最近几秒的说话，中期值约 0.4 秒；换了人说话或麦克风位置变化时约一秒内跟上，单个咳嗽或漏判的提示音只会被限制在小范围内。随后把两轨的人声都调到同一响度（约 −20 LUFS，增益 −15 到 +24 dB）；非人声的声音可以随增益降低，但不会被放大。处理带 300 ms 预读：增益从第一个音节开始生效，后来被识别为提示音的声音会撤回增益；突然大声的新说话人在测量完成前就会被压住，最后由预读峰值限制器防止削波。“音量平衡”滑块在自动平衡之后再让麦克风或其他声音更响。处理只延迟音频本身，时间戳保持不变，导出片段会等待音轨追上片段结尾。

“概览”页“声音”中的三条电平用于确认各轨是否录到声音：开始采集并找到 Apex 窗口后约每秒刷新 10 次，显示该间隔内录入音轨的峰值。电平条采用 −60 到 0 dBFS 的刻度，右侧显示数值；低于 −60 dBFS 显示“静音 / 极低”，设备失败显示“设备不可用”。尚未采集或正在等待游戏时显示对应状态，此时不会监听麦克风。麦克风和其他应用的电平下方显示识别出的人声音量和当前平衡增益（“说话中”表示正在检测到人声；尚未测量时显示“等待人声”）。

结果确认后会等待最多 20 秒，判断是否出现关联击倒。这个等待不会全部加到视频尾部。高伤害助攻或单次结果可以保存；后续连杀合并为长镜头。最长连续素材为 90 秒，分段留 2 秒衔接；同一长镜头的末段即使只剩一次结果也会保留。素材目录默认只输出 MP4；打开开发者模式后，片段旁另有同名 JSON（见“开发者模式”）。失败任务在本次运行期间保留引用，可以重试；退出进程后内存任务无法恢复，已有 MP4 和临时文件不会被删除。

## 目前验证范围

这是可运行的早期版本。已在本机验证真实 Windows 窗口采集、NVENC、三个音轨、重叠导出、保存失败后重试，并用本地 2024 年参考录像运行真实解码、HUD 识别和规则处理。规则场景测试包含五次跨队击倒、长追击切断、重复淘汰、助攻、换弹、90 秒分段和动态内存预算。

HUD 适配首先针对这些参考录像中的中文布局。数字采用本地二值字形匹配，中央提示采用 Windows 本地 OCR；没有 YOLO 或大模型。伤害数量只读取右上角自己的累计伤害，不读取敌方血条、浮动伤害或中央奖励数字。自己的 HUD 名字经多次确认后，用于匹配本人击杀信息，只补充已有中央结果提示的目标身份，不把其他玩家的消息直接当作本人结果。中央识别保留红色敌人名并避开字幕；名字不清晰时建立临时身份，之后识别出名字只更新身份，不另加一人。短暂漏读、名字截断和同一次击倒后的淘汰不会重复计数：淘汰会先找之前击倒、还没被淘汰的同一个人，长名字允许少量字读错；任一方名字读不出时，与 90 秒内最近一次击倒配对。名字不同的两次直接淘汰仍算两人。采集启动时已经显示的结果提示作为历史基线。观战、大厅、结算、训练场或无法匹配关键 HUD 的画面不会继续触发素材。

伤害数字在变化时会滚动，也会和亮色背景粘连，常常读不出；这时保留上次确认的值，并用整行读取（击杀、助攻、伤害）作为备用。读数增加要两次一致才确认；超过 2 秒读不出后出现的增量平均分摊到这段时间，不猜成瞬间高伤。伤害计数不可读时，只要武器弹药和战斗布局仍可确认，就继续识别本人结果提示，连杀可依据确认的击倒/淘汰结果保存；不依赖敌人的血条。单次结果或助攻需要满足上述两项伤害条件才保存。战斗 HUD 读不出持续 10 秒，或观战、死亡回放、冠军等画面持续 3 秒，才视为对局结束；打药、开地图、扔雷不会把一场战斗拆开。

**尚未通过当前版本 Apex 的实战验收，也尚未证明总体精度 ≥95%、召回 ≥90%、误存 ≤10%、游戏平均帧率下降 ≤5%。**小样本回归不能替代留出集。详细证据和限制见 `docs/VALIDATION.md`。实战建议使用无边框窗口；采集受限会报错，不会改用注入或渲染挂钩。

## 开发者模式

在“设置 › 通用”打开“开发者模式”后，采集时会同时写一份 JSON 时间线，用来排查某段为什么保存了、或者为什么没保存。它只做记录，不改变保存规则。采集中切换立即生效，关闭后不再写文件。打开时，概览页还会显示实时的伤害、击杀、助攻读数和记录文件的位置。

- 每次采集（或每次重新打开开发者模式）写一个文件：`<保存目录>/开发者记录/Apex_dev_<日期>_<时间>_<毫秒>_<进程>_<序号>.json`。每写一条记录后文件都是完整的 JSON，程序意外退出也能直接打开。
- 文件结构是 `{"format":"apex-replay-dev-v1","session":{...},"entries":[...]}`。`session` 包含当时的设置、生效的保存标准和 HUD 模板版本。每条记录都有类型 `type` 和时间 `t`；`t` 是采集开始后的秒数，与片段起止用同一条时间轴。
- 主要的记录类型：
  - `hud`：右上角的原始读数 `damage`、`kills`、`assists`，确认后的 `confirmedDamage`、`killCount`、`assistCount`，以及弹药和识别状态。读数变化时写，另外每 10 秒写一次。
  - `damage`：确认的伤害增量 `delta`、累计伤害 `total`，以及这段伤害发生在 `since` 到 `at` 之间。
  - `kill_counter`、`assist_counter`：击杀数、助攻数确认增加（`from` → `to`）。
  - `feed_own`：击杀信息里本人那一行。`victim` 是对方；`knock` 为 true 表示击倒（带红色击倒图标），为 false 表示淘汰。
  - `prompt`、`feed`：中央提示和击杀信息的 OCR 原文，变化时写。`result`：从中央提示识别出的击倒、淘汰、助攻、小队全灭及目标。
  - `rule`：保存规则的每一步判定，包括计入、合并、重复、助攻不达标、生成片段计划、丢弃候选。附带原因，以及 5 秒和 2 秒内的最高伤害 `burst`。
  - `boundary`：对局边界及原因。`clip_published`、`manual_save`：自动片段和手动保存。
- 片段保存成功后，MP4 旁会写一个同名 `.json`，内容是片段信息和这段时间内的记录。每条记录多一个 `clipTime`，即相对视频开头的秒数，可以直接对照视频看。
- 核对时：击倒看 `feed_own`（带击倒图标）和中央提示；击杀看 `kill_counter` 和击杀信息里的淘汰行；助攻看 `assist_counter` 和中央助攻提示。

## 诊断与开发

设置位于 `%LOCALAPPDATA%\ApexPerif\settings.json`，会话日志位于 `%LOCALAPPDATA%\ApexPerif\logs`，开发者记录位于保存目录下的 `开发者记录`。源代码见 `src/`，规则和中文字形模板见 `config/`。

开发构建与诊断命令见 `docs/BUILD.md`。运行包自带 .NET 和 FFmpeg 动态库，第一版需要 Windows 11、支持 HEVC NVENC 的 NVIDIA 显卡及可用的中文 Windows OCR。

系统边界：不注入、不挂钩游戏渲染、不读写游戏内存、不安装驱动、不修改游戏文件、不自动操作游戏。只读取窗口与进程基本信息，使用系统采集接口。没有 EA 认证，也不能保证反作弊零误判。[EA 游戏规则](https://help.ea.com/en/articles/apex-legends/play-by-the-rules/)
